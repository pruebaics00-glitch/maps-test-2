## 2024-05-14 - Direct GeoJSON Aggregation in PostGIS
**Learning:** Returning large spatial datasets by querying individual rows into Java memory and then manually constructing/serializing a GeoJSON FeatureCollection using Jackson causes unnecessary CPU and memory overhead. Using `json_build_object` combined with `json_agg` and `ST_AsGeoJSON(geom)::json` directly in the database is much faster and more memory efficient, effectively shifting the serialization workload to PostGIS. Also, using `COALESCE` is required to ensure an empty JSON array instead of null when the table is empty. Returning a raw string from a Dropwizard endpoint annotated with `@Produces(MediaType.APPLICATION_JSON)` sends the raw JSON without extra quotes.
**Action:** When creating APIs that serve GeoJSON from a PostGIS database, build the complete GeoJSON string directly in the SQL query using PostGIS JSON functions instead of assembling it in the Java application layer.
