**Learning:** [React `useEffect` combining theme change (which requires a MapLibre `setStyle`) and data fetch triggers a full style recalculation on every data load. MapLibre `setStyle` clears layers.]
**Action:** [Decouple the theme configuration from data fetching by using a Ref for dynamic data within the configuration block and handling data synchronization in its own decoupled `useEffect`.]
## 2024-05-02 - [PostGIS Native JSON Aggregation and JAX-RS Byte Array Trick]
**Learning:** [Using PostGIS native JSON aggregation (`json_build_object`, `json_agg`, `ST_AsGeoJSON(geom)::json`) combined with JAX-RS byte array output (`Response.ok(jsonString.getBytes(StandardCharsets.UTF_8))`) drastically reduces memory overhead and bypasses Jackson double-encoding compared to looping through POJOs in Java.]
**Action:** [Prefer database-level JSON aggregation for spatial data, cast ST_AsGeoJSON results to `::json` within aggregates, use `COALESCE` to handle empty sets, and return the result as a `byte[]` in JAX-RS responses.]
## 2024-05-02 - [PostGIS json_agg with COALESCE fix]
**Learning:** [When using `json_build_object` wrapping `json_agg`, if the table is empty, `json_agg` returns `NULL`. `json_build_object` handles `NULL` by generating `{"features": null}` instead of returning `NULL`, causing an outer `COALESCE` to fail and return an invalid GeoJSON with `null` features. The `COALESCE` must be directly around `json_agg` with a cast: `COALESCE(json_agg(...), '[]'::json)`.]
**Action:** [Always apply `COALESCE` with `::json` cast directly on `json_agg` inner calls before wrapping them in outer `json_build_object` constructs to correctly handle empty datasets.]
