## 2025-06-09 - PostGIS JSON Aggregation for GeoJSON Performance
**Learning:** Returning hundreds of entities from the database, creating `Poi` Java objects for them, creating hash maps for properties, using Jackson to serialize the GeoJSON string back into a JSON tree, and finally serializing the entire FeatureCollection into JSON string adds immense Java-side memory overhead and Jackson serialization CPU costs.
**Action:** When building GeoJSON feature collections, prefer PostGIS native JSON aggregation (`json_build_object`, `json_agg`, and `ST_AsGeoJSON`) directly in the SQL query. Remember to use `ST_AsGeoJSON(geom)::json` to prevent it from being a string, and `COALESCE(json_agg(...), '[]'::json)` because `json_agg` on empty tables returns null and fails inside `json_build_object`. Finally, in JAX-RS dropwizard, return raw JSON strings as `Response.ok(jsonString.getBytes(StandardCharsets.UTF_8)).build()` to avoid Jackson double-encoding strings when `@Produces(MediaType.APPLICATION_JSON)` is present.
